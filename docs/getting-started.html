v1.1.0: Complete Usage Guide

This version includes the full desktop workflow: jobs grid, scheduling controls, settings, logs, notifications, and history.

1) Install and launch

  1. Download the installer from latest release.
  2. Run ArchiveSetup.exe and complete installation.
  3. Open Archive from Start Menu or desktop shortcut.
  4. Optional: Open File → Settings and enable Run Archive when Windows starts.

2) Create a directory sync job

  1. Select File → New Job.
  2. Set Job Type to DirectorySync.
  3. Enter Name and optional Description.
  4. Set Source to the folder/file to protect.
  5. Set Destination to an existing backup folder.
  6. Choose sync options:
    • Include subdirectories for recursive copy
    • Delete orphaned destination files for mirror-style behavior
    • Skip hidden and system files for safer defaults
    • Verify copied files for integrity checks
  7. Choose trigger type:
    • Manual for ad-hoc runs
    • One-Time for a specific date/time
    • Recurring using simple controls or cron
  8. Select Preview Operations to review expected actions.
  9. Select Save.

2b) Create an Azure SQL database backup job

  1. Select File → New Job.
  2. Set Job Type to AzureSqlDatabaseBackup.
  3. Enter job Name and optional Description.
  4. Configure source fields:
    • Azure SQL Server = your server host name (for example myserver.database.windows.net).
    • Database = exact database name to back up.
    • Source Profile (Azure SQL) = choose an existing profile or create a new one with a valid Azure SQL connection string.
  5. Configure destination fields:
    • Destination Type = LocalDevice, AzureBlobStorage, or GoogleDrive.
    • Destination Target:
      • LocalDevice: local folder path (example D:\ArchiveBackups).
      • AzureBlobStorage: container or container/prefix (example archive-backups/sql).
      • GoogleDrive: target Drive folder id.
    • Destination Profile (required for Azure Blob and Google Drive) = select existing credentials profile or create a new one.
      • Azure Blob profile secret = storage connection string.
      • Google Drive profile secret = service account JSON payload.
  6. Choose trigger type (Manual, One-Time, Recurring) and save.

2c) Job type quick reference (v1.1.0)

  • DirectorySync: Source = file/folder path, Destination = existing local folder path.
  • AzureSqlDatabaseBackup: Source = Azure SQL server + database + source credential profile, Destination = selected destination type + target + optional destination credential profile.

Current scope: v1.1.0 UI configures one destination per Azure SQL backup job.

3) Run and monitor a job

  1. In the main jobs grid, right-click a job and select Run Now.
  2. Use the Status and Next Run columns for quick health checks.
  3. Open View History for execution details (files copied, warnings, failures).
  4. Use Stop Job if an active run needs to be interrupted.

4) Configure notifications and retention

  1. Open File → Settings.
  2. Enable notifications globally, then choose per-event notifications:
    • Notify on start
    • Notify on completion
    • Notify on failure
  3. Set Keep logs for to your preferred retention period.
  4. Use View Logs from the File menu for troubleshooting.

5) Safe-operating checklist

  • Keep destination outside source to avoid recursive growth.
  • Use a test destination first before enabling delete-orphaned behavior.
  • Prefer folder-level sources instead of entire drive roots when possible.
  • Review history after first scheduled run to confirm expected behavior.

v1.0.0: Usage Guide

This version focuses on core file sync jobs with manual/one-time/recurring scheduling.

1) Install Archive

  1. Download from latest release.
  2. Run ArchiveSetup.exe.
  3. Open Archive.

2) Create a backup job

  1. Select New Job.
  2. Enter job name and optional description.
  3. Choose source file/folder and destination folder.
  4. Select trigger type (Manual, One-time, Recurring).
  5. Configure sync options and save.

3) Preview and execute

  1. Use Preview Operations before first run.
  2. Run manually and verify destination contents.
  3. Check execution history for warnings or failures.

4) Recommended usage tips

  • Use specific source folders instead of full drive roots.
  • Do not place destination inside source.
  • Keep recurring schedules simple until first runs are validated.
